# Visa CRM Email Provider Setup

## Installed behavior

Visa CRM keeps Frappe's standard `Email Account`, SMTP, IMAP, `Communication`, token encryption, and Connected App OAuth implementation. The CRM 1.73 Add Email dialog supports password/App Password input only. It does not expose Frappe's OAuth fields, Connected App selection, or authorization action. Visa CRM overrides only the CRM account-creation API to use correct provider presets, validate only enabled directions, and return safe diagnostics.

Never place mailbox passwords, App Passwords, OAuth client secrets, access tokens, or refresh tokens in source code or site documentation.

## Gmail App Password setup

Use this for a personal Gmail account or Google Workspace mailbox only when App Passwords are permitted by the account and organization.

1. In Google Account Security, enable 2-Step Verification.
2. Create an App Password for the CRM mailbox. Copy the generated 16-character value.
3. In Frappe CRM, open `CRM > Settings > Email > Account > Add Email`.
4. Select `GMail`, enter the complete Gmail or Google Workspace mailbox address, and enter the App Password rather than the normal Google password.
5. Enable Outgoing. Enable Incoming only when CRM should synchronize replies.
6. Set Default Incoming/Outgoing only when this mailbox should be the site default.
7. Create the account. Visa CRM tests IMAP and SMTP independently.

Gmail settings are IMAP `imap.gmail.com:993` with SSL/TLS and SMTP `smtp.gmail.com:587` with STARTTLS. A custom domain does not imply a custom server: a domain hosted by Google Workspace uses the Gmail servers. App Passwords are unavailable for some managed, Advanced Protection, or security-key-only accounts; use OAuth in those cases.

## Gmail OAuth2 setup

OAuth is preferred for Google Workspace and long-lived production access. CRM 1.73 cannot configure OAuth inside its Add Email dialog, so use standard Frappe Desk:

1. In Google Cloud Console, create/select a project, configure the OAuth consent screen, and create a Web application OAuth client.
2. In Frappe Desk search for `Connected App`, or open `/app/connected-app`, and create a Connected App.
3. Set OpenID Configuration to `https://accounts.google.com/.well-known/openid-configuration`, fetch the endpoints, and enter the client ID and encrypted client secret.
4. Add scope `https://mail.google.com/` and query parameters `access_type=offline` and `prompt=consent` for initial authorization.
5. Save, then copy the exact Redirect URI generated by Frappe. Register that exact HTTPS URI and the production site origin in Google Cloud Console.
6. Connect to the provider while logged into Frappe as the mailbox owner.
7. Open `/app/email-account`, create the account with service GMail and Auth Method OAuth, link the Connected App and Connected User, use IMAP `imap.gmail.com:993` SSL and SMTP `smtp.gmail.com:587` TLS, then authorize API access.

Google may require OAuth consent verification for external production use of the restricted full-mail scope. Internal Google Workspace apps can be limited to the organization according to its Google Cloud policy.

## Microsoft 365 / Outlook OAuth2 setup

Use OAuth for Exchange Online. Do not depend on basic username/password authentication.

1. In Microsoft Entra ID open App registrations and create a Web application registration for the tenant.
2. Add delegated Office 365 Exchange Online permissions `IMAP.AccessAsUser.All` and `SMTP.Send`; grant administrator consent where required.
3. Create a client secret and retain its Value securely.
4. In Frappe Desk open `/app/connected-app` and create a Connected App using `https://login.microsoftonline.com/<tenant-id>/v2.0/.well-known/openid-configuration`.
5. Enter the client ID and encrypted client secret. Add `offline_access`, `https://outlook.office.com/IMAP.AccessAsUser.All`, and `https://outlook.office.com/SMTP.Send` as Connected App scopes, then save.
6. Copy Frappe's exact generated Redirect URI into Entra Authentication as a Web redirect URI. Never construct a localhost callback for production.
7. Connect while logged into Frappe as the mailbox owner.
8. Open `/app/email-account`, choose service Outlook.com, Auth Method OAuth, the Connected App and Connected User, IMAP `outlook.office365.com:993` SSL, and SMTP `smtp.office365.com:587` STARTTLS.
9. Ensure IMAP and Authenticated SMTP are enabled for that mailbox in Microsoft 365. OAuth does not remove the mailbox-level SMTP AUTH protocol requirement.

The CRM 1.73 password dialog can be used only for an Outlook account where the provider still permits an App Password/basic SMTP and IMAP authentication. It is not the recommended Microsoft 365 production configuration.

## Diagnostics and operations

- Open a saved Email Account in standard Desk and use `Actions > Diagnose Email Account`, or call `visa_crm.api.email_account.diagnose_email_account` with `email_account` and direction `incoming`, `outgoing`, or `both`.
- Categories are authentication, provider policy, DNS, connection, timeout, TLS, OAuth, and configuration.
- Logs are written to `visa_crm.email` with the mailbox masked and secrets redacted. Certificate verification remains enabled.
- OAuth access and refresh tokens are stored by Frappe in encrypted Password fields on Token Cache. Frappe validates OAuth state and refreshes expired access tokens through Connected App.
- To reconnect revoked OAuth access, open the Connected App/Email Account as the mailbox user and authorize again. Remove stale Token Cache authorization through the standard connected-app flow; never edit tokens directly.
- To remove an account, disable incoming/outgoing first, confirm queued mail is handled, then delete the Email Account through its normal form.

## Production verification

1. Confirm the Frappe Cloud site uses its final HTTPS hostname before registering redirect URIs.
2. Add one test mailbox and verify outgoing and incoming diagnostics separately.
3. Send from a CRM Lead and confirm an Email `Communication` appears in the Lead activity timeline and Email Queue reaches Sent.
4. Reply from an external mailbox and run/await incoming-mail synchronization. Confirm the received Communication retains `email_account` and links to the expected CRM Lead.
5. Test an unknown sender only if `Create Lead from Incoming Emails` is intentionally enabled.
6. Revoke the provider grant, verify a safe OAuth/reconnect error, then reauthorize and confirm token refresh resumes.

Frappe Cloud requires no local SMTP daemon or OS package for these providers. The site must be able to reach provider ports 993 and 587; if credential-free connectivity fails in production, contact Frappe Cloud support with the hostname, port, timestamp, and non-secret diagnostic category.
